# Small exercises before a full release

Use fictional fixtures and approved disposable environments. Keep a short evidence record for each exercise.

| Exercise | Expected evidence |
| --- | --- |
| New rule marker | Fresh parent, child and subagent receive the current version. |
| Update during a run | Supported refresh mechanism delivers the new version before the next relevant action; unsupported cases are explicit. |
| Scope pair | Late initial summary uses plan maintenance; delivered fix with an open failure uses rework. |
| Data prerequisite | Existing but unsuitable sample record is rejected before execution. |
| Concurrent claims | Only one writer acquires a shared mutable sample resource; readers of its role are recognized as dependent. |
| Cleanup failure | Dirty fixture remains unavailable even after a lease expires. |
| Browser recovery | A clipped harmless form triggers a verified resize and recovery before escalation. |
| Uncertain send | Agent checks whether the action succeeded before repeating it. |
| Auth ownership | Closing auth helper leaves the two ongoing test sessions alive. |
| Incomplete results | One unattempted approved check makes the final status incomplete. |
| Incorrect expectation | Agent surfaces a conflict between acceptance criteria and implementation without silently redefining success. |
| Review box | Answerable setup question is resolved; a real product decision is surfaced concisely. |

Record setup, action, expected outcome, observed outcome, evidence reference and follow-up. Loading a rule and following it are separate results.
